A3 · 协作面模块打通地图

issue 是枢纽。绿色 = 链路已存在只需呈现；赭色 = 有缺口，是本次真正要建的。

边机制状态
issue → agent派发（DispatchConfirmDialog）· 回复续跑（issue chat）· 流水线接力（PipelineRunStrip）✓ 已通，时间线里可视化即可
agent → 人needs_input 提问挂起 + 等你回复卡 + 我的工作台聚合⚠ 缺口——2️⃣ spec 已写好待实施，是协作面的地基
issue → 会话issue chat 本身就是 conversation（同一存储）✓ 已通，运行卡「展开对话流」直接复用上周的会话聚合视图
issue → 资源库交付物落库（DeliverablesZone）✓ 已通，时间线交付物卡 + 反向"来自哪个任务"待补
issue → 项目归属关系已有✓ 已通
运行进度 → UItask_tracking Realtime（轮次/耗时/状态边界事件）⚠ 半通——数据在流，但"第 N 轮 · 已 X 分钟"级别的过程可视没做
失败 → 人类型化失败回显（附件失败/空产出/断链）⚠ 缺口——4️⃣ 静默失败契约，与 2️⃣ 同期实施

08组件规格

组件规格语义
状态呈现醒目态用文字徽章：运行中(李紫) · 等回复(赭) · 故障(砖红)；空闲降级为灰点吸收 EvoFlow：裸圆点对非技术用户太隐晦。故障徽章必须携带一行可操作原因（warnline）
主按钮随状态空闲→开始对话 · 运行中→查看运行 · 等回复→去回复(赭) · 故障→修复指引吸收 EvoFlow 三卡三 CTA：按钮即状态出口，先给动作再给解释
头像36px 圆角方块 · 图标或首字 · 组色背景编剧组=李紫 · 美术组=绿 · 工具组=钢蓝。沿用 AgentIconPicker，不引入人脸头像
徽章系统模板(钢蓝) · 自建(默认) · 权限域(赭) · N 技能(默认)权限域取值：个人 / 团队 / 项目（对应 user_id / team_id / project_id 现有字段）
卡片240px 最小宽 · hover 抬升 + 显示操作行主操作 Chat 常绿；系统模板第二操作是 Fork 定制，自建是 配置
正在工作横幅李紫底 · 脉冲点 · 单条（多个时轮播/计数）数据源 = agent_runs status=running（LiveRunsStrip 已有）
等你回复卡赭色系 · 引用 agent 原话 · 去回复按钮needs_input 一等状态（路线图 2️⃣）的 UI 落点，spec 已有
分组编剧组 / 美术组 / 工具组（agent 新增 group 字段，seed 提供默认）用户 Fork 的 agent 继承来源分组，可改
文档编辑内联点击编辑 · ⌘S 保存 = 新版本 · 预览/源码切换沿用 MarkdownEditor/MarkdownBody，去掉"文件"独立标签
