Library Prompts Page

A prompt is any text that can drive a generation, wherever it lives today. One read model gathers the three places it lives, and two surfaces show it with different emphasis: the resource library's Prompts page reads text-first with the picture beside it; the canvas panel picks fast and inserts. Nothing is migrated.

1Same tab, real countPrompts joins the other asset tabs with a count that reflects the unified list, so the number in the sidebar and the tab agree.
2Form and origin are the first two filtersForm is what shape the thing has (template / image / album). Origin is who wrote the text (typed / extracted / captioned). They are separate axes; both are new fields the read model derives, and origin becomes a stored column so nobody infers it from which other columns happen to be filled.
3Picture is beside, not above64px, right-aligned, one per image. The text gets the width. Hovering the thumbnail shows the picture large, the same hover card the canvas panel uses.
4Captioned text is set quieterA caption describes a picture; it did not make it. Same card, muted text, an italic origin tag, no parameter row, and it sorts after extracted and typed prompts by default.
5An album is one card that opensCollapsed it shows the stacked thumbnails and a count; opened, one row per slide with its own text and its own Send. Slides without text stay visible and disabled, so the count is honest.

1Mine firstSegment order is Mine / This project / System because the corpus is the user's own pictures; System comes last until its seeds exist. Counts stay on the personal two.
2Form chips lead the chip rowTemplates / Images / Albums come before the group tags, separated by a hairline. Form is the filter people reach for first when the list mixes pictures and templates.
3Every row shows what it made36px thumbnail, a stack with a count for an album, a dashed empty square for a template with no example pictures. The form tag sits at the row's right edge so the eye can scan it in a column.
4An album previews as its slidesThe slide list replaces the positive block. The selected slide's negative and params show below it. Insert acts on the selected slide only; merging slides is a multi-select the user does, never something the panel does for them.
5Save as template is the promotion pathOn any image or album row it creates a prompt asset in Mine with the text, and links the picture(s) to the examples slot. Files do not move; a template that grows out of use replaces a one-off migration. Save current still saves the aimed node's own text.

5 · Decisions

TopicDecisionWhy
Read modelOne backend endpoint returns PromptEntry rows across templates, prompted images and albums, with scope and project filters. Both surfaces consume it; the resource library's Prompts tab switches to it in the same change.Spec §3.2 already forbids the browser-side query. Two surfaces reading two tables would drift on day one.
OriginStored column on the prompt fields' owner, values typed / extracted / captioned, written by the three writers that exist today. A one-time backfill derives it from gen_params and gen_prompt_json for existing rows.Captions and generation prompts differ in reuse value; inferring that from which columns happen to be filled is the kind of implicit rule that rots.
Album insertionPer slide. Insert and Apply act on the selected slide. Merging is a multi-select the user makes.Your call this round; a merged blob silently loses which text made which picture.
PromotionSave as template creates a prompt asset in Mine and links the picture(s) as example files. No automatic promotion, no migration of the 12 rows.Asset-library rule: files hang off entities, they do not move. A template library that grows from use is worth more than one filled by a script.
Media viewsUnchanged. Picture first, prompt badge stays a badge.Different emphasis for the same data is the whole point; the browsing view already has the right one.
Width600px on Prompts, 340px on Media; 45vh drawer under 1100px with list and preview stacked.Spec §3.1; the drawer rule is inherited from P2.
Keyboard↑↓ rows · →← slides inside an album · ↵ Insert · ⇧↵ Apply all · / search · ⇥ segments · Esc cancels a confirm or form first, then closes.Mirrors the Media grid's roving focus so one set of habits covers both pages.
LanguageEN / 中 toggle, persisted with the panel knobs. A row missing the shown language shows the other with a small note; the toggle greys the missing side.Both languages exist on every source; the old picker's toggle was used.
Entry pointsNode bookshelf button opens Prompts aimed at that node. ⌘K gets one row, "Add from library…". The 420px modal is deleted in the same PR.Spec §2 and §6.
