# Chat Asset Refs v2 (loadout picker · sixth failure reason · issue reply box) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a chat or issue-reply author pick WHICH loadout a mentioned character wears, make "that loadout is not this character's" a typed, user-visible refusal instead of a logged fallback, and give the issue reply box the same Assets tab and staged asset chips the AI chat panel already has.

**Architecture:** Backend: `asset_ref_resolver._pick_loadout` stops falling back and returns a typed failure; the reason vocabulary grows by one on both sides with the existing mirror test. Frontend: the staged-asset chip (`ChatAttachmentPicker`) gains a lazy loadout menu (detail fetched on open, only for scoped assets with ≥ 2 loadouts); `IssueReplyBox` mirrors `AIChatPanel`'s asset wiring (state, fetch, select, chip strip, submit) — the issue backend already resolves `asset_ref` through the same `AttachmentRequest` path (`workflows/issue_lifecycle.py`), so no backend change is needed for Task 3.

**Tech Stack:** FastAPI (typed `AssetRefFailure`), React 19 + TypeScript + Vitest, i18n.

**Spec:** `docs/superpowers/specs/2026-08-28-asset-library-loadout-design.md` §6.5 (chat/agent entry) and P5 plan rulings C/D (`docs/superpowers/plans/2026-09-03-asset-library-p5-agent.md`): v1 fixed the reason vocabulary and sent `loadout_id: null` everywhere; this plan is the deferred "v2 loadout picker brings a fifth reason" the resolver docstring names.

## Global Constraints
- Every user-triggered path returns a typed result and is echoed; no silent fallback where the user chose something.
- Reason vocabulary is mirrored: backend `AssetRefFailureReason` ↔ frontend `NAMED_REASONS` (`AttachmentFailureBanner.tsx`) ↔ i18n strings in BOTH locales; the existing mirror test (find it: grep `attachment_limit_exceeded` under `backend/tests`) must cover the new value.
- `MAX_ASSET_REF_ATTACHMENTS` (frontend `components/chat/attachmentLimits.ts`, backend mirror) applies to the issue reply box too.
- i18n keys, English Title Case, zh values; no emoji; lucide icons; real wire shapes in mocks (`AssetRow.id` string, `loadouts[].id` string); never `git add -A`.

### Task 1: `loadout_not_owned` — a typed refusal, not a fallback
**Files:** `backend/app/services/ai/chat/asset_ref_resolver.py`; `backend/app/schemas/ai_library_chat.py` (if the reason literal is re-declared there); frontend `components/chat/AttachmentFailureBanner.tsx` (`NAMED_REASONS`) + both locales; tests: the resolver's test file + the reason mirror test + `AttachmentFailureBanner.test.tsx`.
**Interfaces:** `AssetRefFailureReason` gains `"loadout_not_owned"`. `_pick_loadout(relations, asset_id, requested)` returns `tuple[Optional[dict], Optional[AssetRefFailureReason]]`: requested and owned → `(lo, None)`; requested and NOT owned → `(None, "loadout_not_owned")` (the caller emits `AssetRefFailure(reason="loadout_not_owned", ...)` and DROPS the reference — a picked outfit the user did not get is worse than no picture); `None` requested → `(default or None, None)`. Rewrite the docstring: the v2 picker exists now. Frontend string `chat.attachmentFailure.loadout_not_owned` (key shape: follow the four existing) = "That Loadout Does Not Belong To This Character" / zh "所选造型不属于该角色".
