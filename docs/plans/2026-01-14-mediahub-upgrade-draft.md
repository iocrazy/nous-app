# MediaHub 升级设计草稿

## 项目背景

MediaHub 是一个抖音视频下载管理系统，需要升级以支持 NAS 本地部署和外网分享。

## 当前架构

- **前端**：React（部署在阿里云）
- **后端**：FastAPI
  - DrissionPage 做抖音视频嗅探
  - 视频下载功能
- **数据/认证**：Supabase 云服务
  - 用户认证
  - 数据存储
  - 视频存储（Storage）

## 需求分析

### 使用场景
- 多人协作使用
- 用户分散在不同地方，都通过外网访问

### NAS 环境
- 外网穿透已配置好，稳定可用
- NAS 性能较强（群晖 920+/923+ 以上或 x86 NAS，内存 8G+）
- 已有域名反代（类似 pichome.heygo.cn）

### 转自托管原因
- 成本考虑
- 存储限制
- 数据隐私
- 统一管理

## 方案选择

讨论了三个方案，最终选择 **方案三：扩展 MediaHub**

### 方案三架构

```
┌─────────────────────────────────────────────────────────┐
│                       NAS (Docker)                       │
├─────────────────────────────────────────────────────────┤
│                                                          │
│   ┌─────────────┐    ┌─────────────┐    ┌────────────┐  │
│   │  MediaHub   │───▶│  Supabase   │    │  视频目录   │  │
│   │   (前端+    │    │  (自托管)    │    │  /videos   │  │
│   │   后端API)  │───▶│  - Postgres │    │            │  │
│   └─────────────┘    │  - Auth     │    └────────────┘  │
│         │            │  - Realtime │          ▲         │
│         │            └─────────────┘          │         │
│         └────────────────────────────────────┘         │
│                    直接读取本地视频                       │
├─────────────────────────────────────────────────────────┤
│                    Nginx 反向代理                        │
│              mediahub.yourdomain.com                    │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
                    外网用户访问
```

### 优势
- 一个系统搞定，架构简单
- 视频直读本地，性能最好
- 单份存储，节省空间
- 完全统一管理在 NAS

## 升级要点

1. Supabase 云 → 自托管到 NAS
2. 视频存储从 Supabase Storage → NAS 本地目录
3. 新增视频分享功能（生成外链）
4. 整体部署到 NAS（Docker）
